## Root causes and changes

The cropped screenshot description did not prove missing header/input/footer.
All three are separately tested at40×12,60×18,80×24,100×30,120×40,160×50.
The header is a basic connection/session row,not P10 branding; transcript gets
h−5 rows; notice,two input rows and the minimal cwd/cost/context footer follow.
Confirmed defects: long drafts hid their tail; long titles clipped; known retry
notices fell through to JSON; failed transitions disabled connection; pre-switch
partial events could be replayed into the new session; normal startup/restart
were unwired. Each now has targeted implementation and regression evidence.

- Draft tail wraps and stays visible; titles wrap through the existing layout.
- Retry attempt/max/delay/error and finished success/failure are rendered only
  when supplied; aborted run uses the actual backend flag. F3 exposes original
  raw events. Unknown events remain safe generic details; original notices have
  an8MiB retention budget. No data/status/model-generated formatting is invented.
- `Launch` uses explicit executable/cwd and existing P02 client. Normal discovery
  and Pi-owned authentication remain intact; no prompt at startup. A cwd inside
  the agent config root is refused. No live test startup was performed.
- Session controller verifies identity around history load. Navigation uses public
  new_session/switch_session,with explicit response fences. Veto/rejected paths
  retain original session/view/draft; successful commands clear only matching
  submitted navigation text. Other unsent edits remain intact.
- F5 explicitly joins old jobs,restarts only the owned child and rehydrates its
  saved session with identity verification. No prompt/tool replay. Unsaved nonempty
  sessions are refused rather than silently lost. No-session fixture restart is
  intentionally unavailable. Automatic reconnect/session picker are out of scope.
- Existing P03 registry/writer remains authoritative. Modal input priority,
  cancellation and draft/focus restore are preserved; no new permission engine.
